## Issues Found

### [HIGH] SSRF in `/api/portal/documents/extract` — AUTO-FIXED
**File:** `src/app/api/portal/documents/extract/route.ts:45`
**Detail:** The `file_url` parameter from the POST body was passed directly to `fetch()` with no domain validation. An authenticated TA or admin could supply any URL (e.g. `http://169.254.169.254/...` or internal services) and have the server fetch it on their behalf.
**Status:** Auto-fixed — added validation that `file_url` must start with `${NEXT_PUBLIC_SUPABASE_URL}/storage/`
**Recommendation:** Confirm `NEXT_PUBLIC_SUPABASE_URL` is set in production env. No further action needed.

### [MEDIUM] Missing RLS on `school_otp_sessions` table
**File:** `supabase/migrations/20261101120000_school_otp_sessions.sql`
**Detail:** Table `school_otp_sessions` stores OTP codes in plaintext and has no `ENABLE ROW LEVEL SECURITY` statement and no policies. All server-side access goes through `createAdminClient()` (service role), so it is not currently exploitable via direct PostgREST calls by anonymous users. However, it is a defense-in-depth gap — if any route ever switches to the user client, OTP codes could leak.
**Status:** Needs manual review
**Recommendation:** Add a migration:
```sql
ALTER TABLE school_otp_sessions ENABLE ROW LEVEL SECURITY;
CREATE POLICY "service_only" ON school_otp_sessions FOR ALL USING (auth.role() = 'service_role');
```

## All Clear

The following were checked and confirmed safe:

- **Hardcoded secrets**: None found in `.ts`/`.tsx` files. All secrets correctly use `process.env.*`.
- **Admin API routes**: All checked — every admin route calls `requireAuth` or checks `getUser()` + role.
- **Portal API routes**: All checked — every portal route calls `supabase.auth.getUser()`.
- **XSS (dangerouslySetInnerHTML)**: 3 usages found, all call `sanitizeHTML()` before rendering.
- **SQL injection**: No raw SQL template literal interpolation found anywhere.
- **File upload validation**: `/api/admin/upload-invoices` validates file presence, size (≤20MB), and required fields.
- **Cron routes**: All protected with `CRON_SECRET` Bearer token check.
- **Monday webhook**: Token verification present; production enforces `MONDAY_WEBHOOK_SECRET`.
- **Squarespace webhook**: Token verification present; falls back to dev mode only outside production.
- **School OTP route**: Email is validated against project's teacher_email before issuing OTP (prevents email enumeration via generic error message).
- **Document extract rate limiting**: 10 requests/minute/IP limit in place.
- **School portal routes**: All use `requireSchoolSession()` from `src/lib/school-auth.ts`.
