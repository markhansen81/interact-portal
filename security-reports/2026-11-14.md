## Issues Found

### [MEDIUM] SSRF — Unvalidated file_url in document extraction route ✅ AUTO-FIXED
**File:** `src/app/api/portal/documents/extract/route.ts:45`
**Detail:** The POST body `file_url` was passed directly to `fetch()` without validating it was a Supabase storage URL. An authenticated TA could supply an arbitrary URL and cause the server to make outbound requests to internal services or external hosts.
**Status:** Auto-fixed
**Fix:** Added validation requiring `file_url` to start with `${NEXT_PUBLIC_SUPABASE_URL}/storage/`. Also added strict `doc_type` whitelist validation (was falling back to generic string rather than rejecting).
**Commit:** in this run

### [MEDIUM] DOMPurify transitive dependency XSS (CVE advisory)
**File:** `node_modules/dompurify` (transitive — not directly imported in app code)
**Detail:** `npm audit` flags dompurify 3.4.1 (≤3.4.5) for two moderate XSS CVEs:
- GHSA-hpcv-96wg-7vj8: Cross-realm IN_PLACE sanitization bypasses sanitization via realm-bound `instanceof` checks
- GHSA-r47g-fvhr-h676: IN_PLACE mode preserves attributes of a clobbered root element

App code uses `sanitize-html` (not DOMPurify directly) for all HTML sanitization. DOMPurify appears only as an unlisted transitive dependency. The vulnerable IN_PLACE mode is not used anywhere in the codebase.
**Status:** Needs manual review — upgrade DOMPurify when a fixed version (>3.4.5) is available
**Recommendation:** Run `npm audit fix` once DOMPurify ships a fix, or identify and upgrade the package that pulls it in.
