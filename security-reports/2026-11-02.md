## Issues Found

### [HIGH] @tiptap/core — ReDoS + prototype pollution
**File:** `package.json` (transitive dependency)
**Status:** Requires manual review
**Detail:** Two HIGH advisories:
- GHSA-cp6q-959q-f8rh: `mergeAttributes()` turns `__proto__` key into executable DOM attributes (prototype pollution / XSS vector)
- GHSA-j95f-988m-3j2f: Quadratic ReDoS in Markdown attribute parsing (≥3.7.0 <3.30.5)

Fix: upgrade `@tiptap/core` to ≥3.30.5.
**Recommendation:** Check the Tiptap version in use and upgrade. The prototype pollution issue is particularly concerning if untrusted content is passed to Tiptap editors.

### [HIGH] prosemirror-view — XSS via paste handling
**File:** `package.json` (transitive dependency via Tiptap)
**Status:** Requires manual review
**Detail:** ProseMirror has an XSS vulnerability in its paste handling. Relevant if Tiptap editors accept paste from untrusted sources.
**Recommendation:** Upgrade with the Tiptap upgrade above.

### [HIGH] DOMPurify — cross-realm XSS in IN_PLACE mode
**File:** `package.json`
**Status:** Needs manual review
**Detail:** DOMPurify has HIGH-severity XSS vulnerabilities (GHSA cross-realm `instanceof` check bypass). However, the codebase uses a **custom** `sanitizeHTML` in `src/lib/sanitize.ts` rather than DOMPurify — so direct exposure depends on whether DOMPurify is also called elsewhere.
**Note:** The custom `sanitizeHTML` is regex-based and does not use a DOM parser — this approach has known limitations (nested tags, CSS-based XSS, attribute-based vectors). Since it is only used for admin-authored templates and school student notes, risk is contained but not eliminated.
**Recommendation:** Verify DOMPurify is not called directly anywhere. Consider replacing the regex sanitizer with `isomorphic-dompurify` (server-safe) to get library-grade protection.

### [HIGH] sharp — libvips inherited CVEs
**File:** `package.json`
**Status:** Requires manual review — upgrade when compatible
**Detail:** `sharp` has HIGH vulnerabilities from libvips (CVE-2026-33327, CVE-2026-33328, CVE-2026-35590, CVE-2026-35591) and libheif. These affect image processing — relevant since this app uses the Next.js Image Optimization API (which uses sharp).
**Recommendation:** Check if a newer `sharp` is available and upgrade.

### [MEDIUM] Admin document upload — no file type or size validation
**File:** `src/app/api/admin/projects/[id]/documents/route.ts:62`
**Status:** ✅ Auto-fixed
**Detail:** The file upload endpoint accepted any file type and had no size limit, allowing an admin to upload executables, very large files, or unexpected content types to Supabase storage.
**Fix applied:** Added a 20MB size limit and an allowlist of types (PDF, images, Office docs, plain text/CSV).

### [MEDIUM] school_otp_sessions table — RLS not enabled
**File:** `supabase/migrations/20261101120000_school_otp_sessions.sql`
**Status:** Requires manual review
**Detail:** The `school_otp_sessions` table (OTP codes, session keys) has no `ALTER TABLE ... ENABLE ROW LEVEL SECURITY`. All current code accesses it via `createAdminClient()` (service role), so no direct bypass exists today — but if any query path uses the user-scoped client, raw OTP codes and session keys would be exposed.
**Recommendation:** Add a migration to enable RLS and add a service-role-only policy:
```sql
ALTER TABLE school_otp_sessions ENABLE ROW LEVEL SECURITY;
-- No public policies: only service role can access
```

### [LOW] Custom sanitizeHTML is regex-based
**File:** `src/lib/sanitize.ts`
**Status:** Requires manual review
**Detail:** The custom sanitizer uses regex patterns to strip `<script>`, `on*` handlers, and `javascript:` URLs. Regex HTML sanitization is inherently fragile (malformed tags, encoding bypasses, CSS `expression()` vectors, SVG-based XSS). Currently only applied to admin-created content and school teacher notes.
**Recommendation:** Replace with `isomorphic-dompurify` for server-safe, library-grade sanitization. Low priority given the restricted use context.
