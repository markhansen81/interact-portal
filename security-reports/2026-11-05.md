### [HIGH] Custom regex HTML sanitizer used in `dangerouslySetInnerHTML`
**File:** `src/lib/sanitize.ts`, `src/components/admin/work-order-template-editor.tsx:216`, `src/components/admin/contract-template-editor.tsx:176,322`  
**Detail:** The app uses a homegrown regex-based `sanitizeHTML()` function instead of a battle-tested library like DOMPurify. Regex HTML sanitizers are frequently bypassed via:
- Nested/malformed tags (e.g. `<<script>script>`)
- CSS expression injection
- SVG-based vectors
- Attribute injection not covered by current regexes
- Mutation XSS

The function is applied to admin-facing template previews — lower risk than user-facing, but still a code smell.  
**Status:** Needs manual review  
**Recommendation:** Replace `sanitizeHTML()` with DOMPurify (server-side via jsdom) or use `sanitize-html` package. At minimum, audit the sanitizer against OWASP XSS cheat sheet vectors. Since this only renders in the admin UI, risk is reduced but not eliminated if template content comes from user-editable fields.

### [MEDIUM] Unauthenticated GET on admin-prefixed route `/api/admin/form-content`
**File:** `src/app/api/admin/form-content/route.ts:4`  
**Detail:** The GET handler reads all rows from the `form_content` table without any authentication check. Any unauthenticated request can retrieve all form content. The PATCH handler correctly requires admin auth, but GET does not.

```ts
export async function GET(request: Request) {
  const supabase = await createClient();
  // No auth check here
  const { data, error } = await query;
```

This is likely intentional (form content drives public-facing forms), but the `/api/admin/` prefix is misleading and inconsistent.  
**Status:** Needs manual review  
**Recommendation:** Either (a) confirm this is intentional and move the route to a non-admin prefix (e.g. `/api/public/form-content`), or (b) add authentication if the data should not be public. Add a comment in the route explaining the deliberate lack of auth.

## All Clear

The following items were checked and confirmed safe:

- **Hardcoded secrets**: No `sk_`, `eyJ`, `api_key =`, `password =`, or `secret =` literals found in `.ts`/`.tsx` source files
- **SQL injection**: No raw SQL string interpolation found — all queries use the Supabase ORM with parameterized inputs
- **Missing auth on admin routes**: All `/api/admin/*` routes check auth via `requireAuth(["admin"])` or `supabase.auth.getUser()` + role check; the one exception (`form-content` GET) is documented above
- **Cron route auth**: All 3 cron routes (`check-expiry`, `update-levels`, `health-check`) verify `CRON_SECRET` before executing
- **Webhook auth**: Monday.com and squarespace webhooks both validate a bearer token
- **File upload validation**: `upload-invoices/extract` validates `file.type !== "application/pdf"` before processing
- **XSS in dangerouslySetInnerHTML**: All 3 usages wrap content with `sanitizeHTML()` (noted above as HIGH risk due to custom regex approach, but not unprotected)
- **Intentionally public routes confirmed**: `lead-form`, `health`, `school/magic-link/*`, `school/otp/*` — these have no auth and that is appropriate
- **School portal routes**: `school/project/[token]/*` routes use token-based access — appropriate for school-facing forms
- **Portal routes**: All TA portal routes check `supabase.auth.getUser()` and return 401 if unauthenticated
